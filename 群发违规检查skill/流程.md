# 群发违规检查流程

## 流程图

```
┌─────────────────────────────────────────────────────────────────┐
│                     海外LP群发违规检查 自动化流程                 │
└─────────────────────────────────────────────────────────────────┘

   [1] 下载/获取数据
          │
          ├──> SmartBI 海外LP群发违规明细.xlsx  (含违规文本)
          │     └─ 由 bi_skill 自动下载（数据范围：当月1号 ~ 今天）
          │
          └──> 钉钉文档「报备文本」              (含合规模板)
                └─ 首次手动导出为 报备文本.xlsx 或 海外益智群发日历-LP（主管填写）.xlsx
                   URL: https://alidocs.dingtalk.com/i/nodes/mExel2BLV542xe22HEGnGE60Wgk9rpMq

   [2] check.py 处理
          │
          ▼
        过滤条件1: 场景 == "续费"          (转介绍 / 拓 等场景全部丢弃)
          │
          ▼
        归一化 + 唯一文本提取（关键性能优化）
          │   把 N 条违规文本归一化后去重成 K 个唯一文本
          │   实测 11829 条 → 42 个唯一文本，秒级完成
          ▼
        过滤条件2: max_similarity(唯一文本, 报备文本池) < 0.90
          │       (≥0.90 视为已报备 → 剔除；结果按文本缓存复用)
          │
          ▼
        同文本去重: drop_duplicates([LP姓名, 归一化文本])
          │       (同一 LP 的相同违规文本只算 1 次违规)
          │
          ▼
        按 [小组, LP姓名] 聚合 -> 统计 续费违规条数
          │
          ▼
        自检：BI 原始 → 最终统计 链路核对（任何一步为 0 / 续费占比 < 5% 中止）

   [3] 输出
          │
          ├──> 违规统计_YYYYMMDD.xlsx
          │      sheet1: 违规统计  (小组、LP姓名、续费违规条数)
          │      sheet2: 违规明细  (剔除报备 + 文本去重后的逐条记录 + 相似度)
          │      sheet3: 命中报备(已剔除)  (留底审核)
          │
          └──> broadcast.py 钉钉播报
                  ├─ 按小组分组
                  ├─ 每组一张 markdown 表格
                  └─ 每组违规数最多的 LP 标红
```

## 关键决策点

| 决策 | 选择 | 原因 |
|------|------|------|
| 相似度算法 | SequenceMatcher | 标准库 `difflib`，无需额外依赖；对中文短文本表现稳定 |
| 阈值 | 0.90 | 用户指定 90% |
| 文本归一化 | 去空白+标点+小写 | 避免标点/空格差异降低相似度 |
| **唯一文本缓存** | 先去重再算相似度 | N 条记录通常只有 K 个唯一模板，K << N，把计算量降到原来的 1/N |
| 长度差跳过 | 长度差 > 60% 直接跳过 | 提速，差距过大相似度必然低 |
| 场景过滤 | 仅保留「续费」 | 用户指定剔除转介绍 |
| **同 LP 同文本去重** | drop_duplicates([LP, norm_text]) | 用户规则：同一 LP 群发同一段文本不管多少次都算 1 次违规 |
| 排序 | 续费违规条数倒序 | 让最严重的 LP 排在最上 |
| 数据范围 | 当月1号 ~ 今天 | run.py 自动按 date.today() 取月初 |
| **路径策略** | `Path(__file__).parent` 拼相对路径 | 不写死任何 `C:\Users\<用户名>` 绝对路径，保证可交接 |
| **自检** | 写出前打印链路核对，异常即中止 | 防止字段错位 / 续费列被改名等情况静默吞掉违规 |

## 字段映射规则

`check.py` 通过 `pick_col()` 自动模糊匹配实际列名：

| 标准字段 | 候选列名 |
|----------|----------|
| 小组 | 小组 / 组别 / 团队 |
| LP姓名 | LP姓名 / LP / 姓名 / 班主任 |
| 场景 | 场景 / 违规场景 / 群发场景 |
| 违规文本 | 违规文本 / 消息内容 / 群发内容 / 文本 / 内容 |

如果 BI 报表后续改字段，更新对应 `*_COL_CANDIDATES` 即可。

## 钉钉文档报备文本的处理

钉钉文档导出的 Excel 可能有多个 sheet 或不规则列结构，`load_baseline_texts()` 的策略：
- 读取所有 sheet
- 取所有非空字符串单元格
- 长度 ≥ 8 字符的纳入候选池
- 自动去重

这样即使文档格式有调整也能容错。

## 反模式黑名单（详见 SKILL.md）

简版速记：
1. ❌ 把转介绍 / 拓美术 等场景纳入统计
2. ❌ 在脚本或文档中写绝对路径（`C:\Users\<用户名>\...`）
3. ❌ 直接拿 BI 行数当违规数（必须走过滤链路）
4. ❌ 跳过相似度过滤直接播报
5. ❌ 复用旧的明细 Excel（默认每次重新下载）
6. ❌ 把同一 LP 的相同模板按发送次数计数
7. ❌ 把「合计 / 总计 / 小计」行误当 LP
8. ❌ 静默吞掉数据链路异常（自检不通过必须中止）

## 运行

```bash
# 一键（默认数据范围：当月1号 ~ 今天）
python <SKILL_DIR>/run.py

# 分步
python check.py 海外LP群发违规明细.xlsx --baseline 报备文本.xlsx
python broadcast.py 违规统计_YYYYMMDD.xlsx
```

> `<SKILL_DIR>` 表示当前 skill 文件夹所在路径，请按各自电脑展开。

## 实测样本（2026-05-01 ~ 2026-05-26）

| 步骤 | 数据 |
|------|------|
| BI 原始 | 12281 行 |

| 唯一文本 | 42 个 |

## 首次使用前的准备

1. 把整个 `群发违规检查skill` 文件夹放到任意位置（不限用户名 / 盘符）
2. 浏览器打开钉钉文档：https://alidocs.dingtalk.com/i/nodes/mExel2BLV542xe22HEGnGE60Wgk9rpMq
3. 右上角「导出」→ Excel
4. 重命名为 `报备文本.xlsx`
5. 放到 skill 文件夹根目录
6. 钉钉文档更新时同步替换该文件
7. 配置 `~/.claude/secrets/intro_monitor.env` 中的 `DINGTALK_WEBHOOK_URL`
8. 安装依赖：`pip install pandas openpyxl requests`
