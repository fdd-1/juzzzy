# 路径约定

为了让 skill 能裸交接给任何人（不同用户名、不同盘符、不同操作系统），代码与文档遵守同一组路径规则。

## 总则

> **绝对路径不得出现在任何代码、注释、SKILL.md、流程.md、references/ 文档里。**

唯一例外是文档中要演示「用户应该把文件放到哪儿」的占位写法 `<SKILL_DIR>/...`，明确标记为占位，不是实际路径。

## 代码层

| 资源 | 写法 | 备注 |
|------|------|------|
| skill 根目录 | `Path(__file__).parent` | `run.py` / `check.py` / `broadcast.py` 通用 |
| skill 根目录下的文件 | `Path(__file__).parent / "海外LP群发违规明细.xlsx"` | 不要写绝对路径再 `os.path.join` |
| 用户级配置 | `Path.home() / ".claude" / "secrets" / "intro_monitor.env"` | 跨平台 |
| 同用户其他 skill | `Path.home() / ".workbuddy" / "skills" / "bi_skill" / "bi_skill.py"` | 缺失时优雅降级 |

## 文档层

- 命令示例统一用 `python <SKILL_DIR>/run.py`，不写 `C:\Users\xxx\...`。
- 描述文件位置统一用 `<SKILL_DIR>/报备文本.xlsx`。

## 自查命令

接手后建议先跑一次：

```bash
grep -RIn "C:\\\\Users" .       # macOS/Linux 或 git-bash
findstr /S /I "C:\\Users" *.*   # Windows cmd
```

应当无任何命中（references/ 也不应有）。如果有，说明回潮了，按本规则改回相对写法。

## 为什么

历史上文档和代码都写过 `C:\Users\<某用户名>\Desktop\群发违规检查skill\run.py`。这种路径在以下场景全部失效：

1. 任何其他 Windows 用户名
2. 把 skill 放到 D 盘或 OneDrive 同步目录
3. macOS / Linux 同事接手
4. 用 CI / 容器跑

写成相对/Path.home() 派生路径就一次解决。
