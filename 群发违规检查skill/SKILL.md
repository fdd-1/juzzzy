## 业务逻辑

### 数据来源

| 文件 | 用途 | 获取方式 |
|------|------|----------|
| 海外LP群发违规明细.xlsx | 原始违规明细（含违规文本） | 从 SmartBI「海外后端 / 服务 / 群发」目录下载（run.py 自动调用 bi_skill） |
| 报备文本.xlsx 或 海外益智群发日历-LP（主管填写）.xlsx | 已报备的合规模板文本 | 从钉钉文档导出（首次手动一次） |

> 钉钉文档 URL：https://alidocs.dingtalk.com/i/nodes/mExel2BLV542xe22HEGnGE60Wgk9rpMq
> 该文档需登录访问，脚本无法直接抓取。首次使用前请把文档导出为 Excel 放到 skill 文件夹根目录。
> run.py 优先找 `报备文本.xlsx`，找不到则回落到 `海外益智群发日历-LP（主管填写）.xlsx`。

### 处理规则

1. **场景过滤**：只保留 `场景=续费` 的违规记录，丢弃 `转介绍 / 拓美术 / 拓叫叫 / 拓英语` 等其他场景
2. **文本归一化 + 唯一文本缓存**：所有违规文本先归一化（去空白/标点/小写），然后只在唯一文本集合上算一次相似度并缓存。把 N 条记录的相似度计算降到 K 个唯一文本（实测 11829 条 → 42 个唯一文本，秒级完成）
3. **报备相似度判定**：每条唯一违规文本与所有报备文本逐一计算相似度（SequenceMatcher），最高分 ≥ 90% 视为已报备 → 剔除
4. **同文本去重（关键规则）**：剔除报备命中后，**同一 LP 的相同违规文本只算 1 次**（按 `LP姓名 + 归一化文本` 去重）
5. **统计**：按「LP姓名 + 小组」统计剩余的「续费违规条数」
6. **播报**：以小组为维度在钉钉群播报，每组一个 markdown 表格，每组违规数最多的 LP 姓名标红

### 列名约定

明细表实际列名（根据 BI 报表，可能需要根据下载结果对齐）：
- `小组` / `LP姓名`
- `场景`（续费、转介绍、拓美术…）
- `违规文本` / `消息内容`（要查相似度的字段）
- `违规日期` / `发送时间`

报备文本表至少包含：
- `报备文本` 或 `文本` 列（脚本会自动取所有非空字符串列拼接为候选池）

## 反模式黑名单（DO NOT）

下面这些行为都是历史踩过的坑，禁止再做：

1. **不要把转介绍 / 拓美术 / 拓叫叫 / 拓英语 等非续费场景纳入统计或播报。** 该 skill 业务上只看「续费」场景，混入会让违规数失真。
2. **不要在脚本里写任何 `C:\Users\<具体用户名>\...` 的绝对路径。** 一律 `Path(__file__).parent` 拼相对路径。SKILL.md / 流程.md 示例命令也不要带具体用户名，用 `<SKILL_DIR>` 占位。
3. **不要直接拿 BI 原始行数当违规数。** 必须经过：去空 LP / 去合计行 → 续费过滤 → 相似度剔除报备 → 同 LP 同文本去重 后再统计。
4. **不要跳过相似度过滤直接播报。** 报备文本变更后阈值仍是 0.90，未走过滤会把已报备模板误报为违规。
5. **不要复用上次的 `海外LP群发违规明细.xlsx`。** 每次执行须由 `run.py` 重新下载（数据范围：当月 1 号至今），除非用户明确说「这个文件我已经下载了」。
6. **不要把同一 LP 的相同模板按发送次数计数。** 同一 LP 同一段违规文本永远算 1 次违规。
7. **不要把违规统计表里的「合计 / 总计 / 小计」行误当成 LP。** `check.py` 已对 LP 列过滤这些关键字，新增字段时同步保留过滤。
8. **不要静默吞掉行数差异。** `check.py` 跑完会打印「自检」段，若 BI 原始行 → 最终统计的链路有任何步骤数据为 0 或异常掉量（>95%），必须排查后再播报。

## 校验自检（必须保留）

`check.py` 在写出 Excel 之前会打印一段自检表，建立 BI 原始行数到最终统计行数的链路核对：

```
[自检] 数据链路核对
  BI 原始行         12281
  ├ 有效违规        12253   (剔除空 LP / 合计行 28)
  ├ 续费场景        11829   (剔除非续费 424)
  ├ 唯一文本           42
  ├ 命中报备(剔除)   7124
  ├ 未命中            4705
  ├ 同 LP 同文本去重   109   (去重 4596)
  └ 最终统计 LP 数     58    合计违规 109
  ✓ 链路一致
```

判定规则：
- 任何一步数据为 0：终止流程并报错（数据源很可能异常）。
- 续费场景 / BI 有效违规 < 5%：警告（场景列可能没识别到「续费」）。
- 最终统计违规数 != 违规明细 sheet 行数：终止流程并报错（输出与统计不一致）。

`run.py` 透传 `check.py` 的退出码，校验失败会直接中止后续播报。

## 使用方式

### 端到端运行

```bash
python <SKILL_DIR>/run.py
```

`run.py` 会顺序执行：
1. 通过 `bi_skill` 下载「海外LP群发违规明细」
2. 加载本地 `报备文本.xlsx`
3. 调用 `check.py` 做相似度过滤 + 统计 + 自检
4. 调用 `broadcast.py` 播报到钉钉

### 仅基于现有 Excel 检查

```bash
python check.py 海外LP群发违规明细.xlsx --baseline 报备文本.xlsx --output 违规统计_YYYYMMDD.xlsx
```

### 仅播报已统计结果

```bash
python broadcast.py 违规统计_YYYYMMDD.xlsx
```

## 输出

- `违规统计_YYYYMMDD.xlsx`：剔除报备命中后的续费违规统计（按 LP）
- 终端打印 markdown 报告 + 自检表
- 钉钉群推送：每组一个表格，违规数最多的 LP 标红

## 阈值与配置

| 项 | 默认值 | 说明 |
|-----|--------|------|
| 相似度阈值 | 0.90 | ≥0.90 视为已报备命中 |
| 仅保留场景 | 续费 | 其他场景一律剔除 |
| 同 LP 同文本 | 算 1 次 | 同一 LP 的相同违规文本只算 1 次违规（按归一化文本去重） |
| 最低播报违规数 | 1 | 违规条数 ≥ 1 的 LP 才入表 |
| 数据范围 | 当月 1 号至今 | run.py 自动按当前日期取月初到今天 |
| 自检最小占比阈值 | 5% | 续费占比 < 5% 视为异常 |

## 钉钉播报配置

复用现有 `~/.claude/secrets/intro_monitor.env` 中的 `DINGTALK_WEBHOOK_URL`。

## 注意事项

- BI 报表表头可能在第 2~4 行，`check.py` 会尝试 header=0/1/2/3 自动适配（实测下载的报表 header=3）
- **性能**：先归一化全部违规文本并去重为唯一集合后再算相似度，K 个唯一文本 × M 个报备文本即可，无论原始多少行都能秒级完成
- 转介绍场景全部剔除，**不进入**统计与播报
- 同一 LP 的相同违规文本仅算 1 次违规（避免一条群发模板重复触发计数）
