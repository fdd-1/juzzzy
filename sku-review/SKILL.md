# SKU复盘自动化 Skill

每月自动化执行海外SKU复盘：下载BI报表 → 提取数据 → 匹配人群 → 计算指标 → 对标分析 → 生成报告。

## 使用方式

用户通过 `/sku_review` 调用。

## 支持区域

| 区域参数 | 五级部门筛选 | 区域等级筛选 | 备注 |
|---------|-------------|-------------|------|
| `gangao` | 港澳益智教学服务区 | 港澳 | 港澳市场 |
| `oumeiao` | 欧美澳益智教学服务区 | ≠港澳 且 ≠台湾 | 含北美/欧洲/澳洲等所有非港澳非台湾区域 |
| `taiwan` | 台湾益智教学服务区 | 台湾 | 台湾市场 |

> 区域筛选实际值以 BI 报表当期下拉值为准。每次跑全量校验前先用 `--list-regions` 抽样核对。

## 前置准备

将以下文件放入 `data/{月份}/` 目录（区域共用，按月份归档）：
- **正式池文件**：文件名包含"正式池"（如 `4月正式池-04.01-v1.xlsx`）
- **SKU测算文件**：每个区域一份，文件名需包含 区域名+SKU（如 `港澳4月SKU复盘-0421.xlsx`、`欧美澳4月SKU复盘.xlsx`、`台湾4月SKU复盘.xlsx`）

BI报表会按区域自动下载，也可手动放入（文件名含"主订单宽表"+区域标识）。

## 执行命令

> 以下命令默认在 Skill 根目录（`sku-review/`）下执行。如果当前目录在别处，先 `cd` 到 Skill 根目录，或把 `run_sku_review.py` 替换为绝对路径。

```bash
# 单区域复盘（指定月份）
python run_sku_review.py --region gangao --month 4 --year 2026

# 单区域复盘（指定日期范围）
python run_sku_review.py --region taiwan --start 2026-04-01 --end 2026-04-30

# 全区域批跑（依次跑 港澳/欧美澳/台湾，输出独立子目录）
python run_sku_review.py --region all --month 4 --year 2026

# 跳过BI下载，使用已有文件
python run_sku_review.py --region gangao --month 4 --year 2026 --skip-download
```

## 跨月课包结构对比（手动二次分析）

单月复盘已经输出 `套餐明细_{区域}_{月}.csv`、`SKU精细对标_{区域}_{月}.xlsx`、`SKU复盘分析_{区域}_{月}.html`。需要做"3月 vs 6月课包结构差异 + 客单价归因"这类跨月分析时，按下面规约写一次性脚本（不要塞进 `run_sku_review.py`，跨月需求每次维度不同）：

**输入**：两期复盘的 `套餐明细_*.csv`（订单×套餐粒度）+ `SKU精细对标_*.xlsx`（实际vs测算 ASP/单课时价）

**关键聚合维度**（一次出齐，缺一就解释不了客单价异动）：
1. **套餐类目**：按关键字分组（SVIP / 学情限定 / 全量限定 / 升舱包 / 早鸟包 / 全量包 / 其余/常规 / 近期结课 / 体验包(14) / 总监特批）— 优先级匹配，限定包必须排在全量前面
2. **课时段**：从套餐名 `(\d+)课时` 提取后分桶 ≤20 / 21-60 / 61-90 / 91-130 / ≥150
3. **SKU节点**：直接用 CSV 中的 `SKU节点` 列（升舱/早鸟/其余）— 来源是正式池池子节点2
4. **ASP档位**：按套餐 ASP 分桶 <4k / 4-6k / 6-8k / 8-10k / 10-13k / ≥13k

**每个维度都要算**：订单数、占比、ASP、含积分单课时价（= GMV / Σ(GMV/含积分单价)）、Δ占比、ΔASP、Δ单课时价

**客单价异动归因写法**：
- 综合ASP升 + 单课时价降 → 高总价大课时包（如618学情150课时 ASP15088）占比上升
- 综合ASP降 + 单课时价升 → 低总价短课时包（如近期结课/体验包）占比上升
- 两者同向 → 套餐 mix 整体降级或升级

**输出形式**：HTML（顶部 4 KPI 卡 + 综合摘要表 + 每维度对比表 + 文字归因块），偏差>15% 红色 / 5-15% 黄色。**不要再生成额外的 markdown 报告**，HTML 一份就够。

参考实现：[output/20260611_6月复盘/对比分析/_build_html.py](output/20260611_6月复盘/对比分析/_build_html.py)（生成"6月vs测算+3月vs6月"双对比的样板）。

## 分析逻辑

1. **人群分类**：正式池"当前课包顺序"=1为一续，>1为多续，=0排除
2. **套餐分类**：从套餐名称匹配关键词（升舱/早鸟/其余/全量限定/学情限定/SVIP/全量）
3. **指标计算**：
   - ASP = 总金额 / 订单数
   - 含积分单课时价 = 总金额 / 课时数（含积分）
   - 不含积分单课时价 = 总金额 / 课时数（不含积分）
   - 占比 = 套餐订单数 / 同人群总订单数
4. **对标**：实际指标 vs SKU测算文档中的预算指标

## 边界处理

### SKU测算文件表头位置每月可能不同（重要）

**每个月的 `*SKU&测算*.xlsx` 文件由业务手工维护，sheet 名和表头位置都可能变化**。常见两种结构：

**结构A（旧 — 4月模板）**
- Sheet 名：`SKU测算&实际对比`
- 含积分块在 R5-R8，不含积分块在 R13-R16
- 列：col4/5=一续测算ASP/单价, col8/9=多续测算, col12/13=综合测算

**结构B（新 — 6月v3 港澳模板）**
- Sheet 名：`港澳SKU&测算`（首个 sheet，没有"对比"二字）
- 数据散落在右侧（col38-54），按"含积分 / 不含积分"分两块
- 关键锚点：
  - col38 单元格 = `含积分` 或 `不含积分`（区域起始标记）
  - 锚点下方第 1 行：col39=预估单量, col41=预估GMV, col43=对应总课时, col47=`预估ASP`, col49=单课时价格
  - 锚点下方第 2 行：sub-header（一续/多续）
  - 锚点下方第 3-7 行：升舱 / 早鸟 / 其余 / 全量(=综合) / 综合汇总（label 为空，仅 col47 有值）
- 列含义：col47/48 = 一续/多续 ASP；col49/50 = 一续/多续 含积分单课时价；col51/52 = 一续/多续 不含商务单课时价

**`extract_budget_from_sku` 自适应策略**
1. 优先匹配 sheet 名含 "测算" + "对比"；找不到时退到含 "SKU"+"测算" 的首个 sheet
2. 用 `read_only=True` 加载（v3 文件 28MB+，普通模式可能数分钟），缓存前 80 行到 dict
3. 在 col 30-70 范围搜索关键字 `预估ASP`，定位 ASP 列号 `asp_col`
4. 在 col(asp_col-9) 区域（即 col38）搜索 `含积分` / `不含积分` 两个区域起始标记
5. 每个起始标记下方第 3 行起为数据行；遍历节点行（升舱/早鸟/其余/全量→映射"综合"），读 col(asp_col)/asp_col+1 = 一续/多续 ASP，col(asp_col+2)/asp_col+3 = 一续/多续单课时价
6. label 为空但 ASP 列有值的行 = 综合汇总 → 写入 `(kind, '综合', '综合')`
7. 找不到 `预估ASP` 锚点时 fallback 到结构A 的固定行列（保证旧文件兼容）

**新增/微调表头时的修复路径**
- 业务方把"预估ASP"改成"预估客单价"等：在 `extract_budget_from_sku` 的关键字数组里加同义词
- 列数变了（比如 col 47 → 50）：锚点搜索逻辑会自动跟随，不用改代码
- 加了第三个区域（如"含商务" / "不含商务"）：在 `kind_positions` 列表的过滤集合里加上对应字符串

校验通过的标志：跑完日志中 `预算数据: N 个组合`，N 应该是 **18**（含/不含积分各 9 项 = 4节点×2人群 + 综合×2 + 综合汇总×1）。如果 N=0，说明锚点没找到，先手动用 `python -c "from openpyxl import load_workbook; ..."` 看一下 col38 / col47 区域。

### BI下载失败

- 默认重试 3 次，每次间隔 5 秒（已在 `download_bi_report` 实现）
- 3 次失败后**不要静默跳过**，打印明确报错并退出，提示手动下载路径
- 检查项：BI 报表名是否更名、日期字段是否变更、网络/VPN、`bi_skill` 配置是否过期
- `--region all` 模式下任一区域失败：失败区域记入错误清单但不中断其他区域；末尾汇总打印失败列表，退出码 ≠ 0

### 数据筛选后为空
- 触发条件：`extract_bi_data` 返回 0 行 或 `match_orders_with_pool` 返回空
- 处理：**立即停止该区域分析**，不要生成空报告
- 自查顺序：
  1. 确认筛选字段名是否变更（`五级部门`/`区域等级` 是否被改名）
  2. 确认筛选值是否仍存在（如"港澳益智教学服务区"是否被改成"港澳服务区"）
  3. 确认日期范围内 BI 是否真的有订单
  4. 确认正式池文件月份是否对得上（4月复盘必须用4月正式池，不是3月延用）

### 对标偏差过大
偏差 = (实际值 - 预算值) / 预算值

| 偏差绝对值 | 标记 | 处理 |
|-----------|------|------|
| ≤ 5% | 绿色 / 无标记 | 正常 |
| 5%–15% | 🟡 黄色高亮 | 写入报告"关注项"段，附数据来源 |
| > 15% | 🔴 红色高亮 | 写入报告"异常项"段，必须人工复核才能交付 |
| 预算缺失 | ⚪ 灰色 | 标"无预算"，不参与偏差统计 |

实现位置：`generate_report.py` 中渲染对标单元格时按阈值打底色；HTML 报告顶部加"异常项汇总"块。

### 文件未找到 / 多份匹配
- 找不到正式池或 SKU 测算文件：明确报错，列出搜索路径，不要假装继续
- 同关键字命中多份：按修改时间取最新，但**打印命中列表**让用户能识别是否选错
- Excel 临时锁文件 `~$*` 已在 `find_file_in_data` 排除

### 字段缺失 / 表头变更
- BI 表头检测以"用户ID"为锚点；若锚点找不到，明确报错"BI报表表头结构变更"，不要 fallback 到列号硬编码
- 必填字段缺失（套餐名称/支付金额/课时数）→ 直接抛 `ValueError`，列出缺失字段名

## 反模式（不要这样做）

- ❌ **不要假设 SKU 测算文件每个月都长一样**。表头位置、sheet 名、列号都可能变。`extract_budget_from_sku` 已用关键字锚点 (`预估ASP` + `含积分`/`不含积分`) 自适应，新结构请扩展同义词，不要回到硬编码行号。
- ❌ **不要把 `不含商务单课时价` 当成 `不含积分单课时价`**。结构B 的 col51/52 实际是"不含商务"（口径=不算9折商务渠道折扣），不是"不含积分"。"不含积分单课时价"在 R42 起的"不含积分"区域里，对应同一节点 col49/50。**两个口径不能互换**。
- ❌ **不要直接用 28MB 测算文件的 `load_workbook` 默认模式**（耗时数分钟）。一律用 `read_only=True` + dict 缓存前 80 行。
- ❌ **不要用其他区域的BI报表做某区域复盘**。港澳复盘必须用港澳筛选条件下的数据，不能用全海外宽表"看着差不多"就交付。三区域订单结构差异极大，混用会污染ASP和占比。
- ❌ **不要复用上月的BI下载文件**（除非用户明确说"这个文件我已经下载了"）。BI 数据按月份重切，每次复盘必须新建 `data/{月份}/` 目录重新下载。这是 [全局规则](../../.claude/CLAUDE.md) 的明确要求。
- ❌ **不要把"区域等级=港澳"和"五级部门=港澳益智教学服务区"二选一**。两个字段都要筛，缺一会带入跨区订单（例如挂在港澳部门下但实际是台湾区域的订单）。
- ❌ **不要把"欧美澳"实现为"区域等级=欧美澳"**。BI 中没有"欧美澳"这个区域等级值，欧美澳是若干区域等级的并集。正确做法是 `区域等级 NOT IN (港澳, 台湾)` 配合 `五级部门=欧美澳益智教学服务区`。
- ❌ **不要在数据为空时仍生成报告**。空报告会被误读成"该区域无业绩"。空数据必须报错退出。
- ❌ **不要静默吞掉 SKU 预算提取异常**。当前代码用 `try/except` + `⚠` 警告，但偏差对标会变成"无预算"，结论失真。预算文件解析失败应该让用户知道——打印异常详情，并在最终报告顶部明确"本期未对标"。
- ❌ **不要把人群顺序=0 的订单当多续**。`COHORT_RULES` 里 0 → None 表示池外，必须排除而不是归入"多续"。
- ❌ **不要在套餐分类用 `if "全量" in name` 而不考虑顺序**。`PACKAGE_CATEGORIES` 是按优先级匹配的列表，"全量限定"必须排在"全量"前面，否则限定包会被错分。
- ❌ **不要在月中跑当月复盘**。BI 当月数据未完结，ASP 会偏低。复盘默认跑上一个完整月。
- ❌ **不要把多个区域的输出写到同一个目录**。`--region all` 必须按区域分子目录，否则文件互相覆盖。

## 校验清单

每次交付前按顺序自查（顺序不能乱）：

### 输入校验
- [ ] BI 报表的月份和复盘月份一致（看文件名 + 抽查首尾行的支付时间）
- [ ] 正式池文件月份和复盘月份一致
- [ ] SKU 测算文件区域和当前 `--region` 一致（不要拿港澳测算去对标台湾）
- [ ] BI 表头包含：用户ID、套餐名称、用户实际支付金额、课时数（含积分）、课时数（不含积分）、五级部门、区域等级
- [ ] 正式池表头包含：用户ID、当前课包顺序、池子节点2

### 筛选校验
- [ ] 筛选后订单数 > 0
- [ ] 筛选后区域等级值唯一（港澳/台湾区域）或符合排除规则（欧美澳）
- [ ] 一续 + 多续 + 排除 = 总订单数（不应有遗漏）
- [ ] 套餐分类无"其他"或"其他"占比 < 5%（占比过高说明 `PACKAGE_CATEGORIES` 没覆盖新套餐）

### 计算校验
- [ ] ASP 落在合理区间（参考上月 ±30%，超出要查异常订单）
- [ ] 含积分单课时价 ≤ 不含积分单课时价（否则字段映射反了）
- [ ] 各套餐占比之和 ≈ 100%（容忍 ±0.5% 浮点误差）
- [ ] 综合行的订单数 = 各套餐订单数之和

### 对标校验
- [ ] 红色异常项（偏差 >15%）已逐条人工复核
- [ ] 黄色关注项已在报告中标注原因或归因方向
- [ ] "无预算"项已确认是否需要补预算（而不是预算文件解析失败）

### 输出校验
- [ ] HTML 报告打开正常，色阶渲染正确
- [ ] Excel 对标表中预算列、实际列、偏差列三列齐全
- [ ] CSV 明细行数 = 筛选后订单数（去重前）
- [ ] 输出目录命名为 `{YYYYMMDD}_{月份}复盘/{区域}/`，未覆盖历史
