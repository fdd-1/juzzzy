> 本文档定义海外思维服务周报（4.1-4.6 六个板块）的端到端自动化流程
> 触发：用户说"生成本周服务周报"或"做 X 月 X 日 - X 月 X 日的周报"

## 一、时间窗口规则

| 项目 | 规则 |
|---|---|
| 当月1号 | 当前月份的第一天 |
| 上周一 | 距今最近的过去周一 |
| 上周日 | 距今最近的过去周日 |
| 上周五 | 上周日 - 2 天 |
| 上周四 | 上周日 - 3 天 |

- 当月1号 = 2026-06-01
- 上周一 = 2026-06-01
- 上周日 = 2026-06-07
- 上周五 = 2026-06-05
- 上周四 = 2026-06-04

### 使用 SmartBI Data CLI 自动下载

**工具**：smartbi-data-cli（与本项目同级目录下任意 `smartbi-data-cli-internal-*`，或通过 `$env:SMARTBI_CLI_DIR` 指定绝对路径）

**凭据**（环境变量；**严禁**在脚本/文档/JSON 里写实际值）：
```powershell
$env:SMARTBI_USERNAME = "<your-username>"
$env:SMARTBI_PASSWORD = "<your-password>"
# 可选：smartbi-data-cli 不在项目同级目录时
$env:SMARTBI_CLI_DIR = "<smartbi-data-cli-internal-* 绝对路径>"
```

- **4.1 板块**：上周一到上周日

```powershell
python service_weekly_report\scripts\download_smartbi_reports.py
```

**输出路径**（项目相对路径）：

## 三、数据整合规则

### 3.1 通用数据格式化规则（适用所有板块）

| 列头特征 | 格式 | 示例 |
|---|---|---|
| 含"占比"/"率"且不含"加和" | 百分比，保留两位小数 | `0.8573` → `85.73%` |
| 含"执行率加和" | 数值，保留两位小数（不带%） | `5.35` |
| 列尾是"数"/"人数"/"次数" | 整数 | `142` |
| 其他数值列 | 保留两位小数 | `1.55` |

### 3.2 通用数据清洗规则
- forward-fill 合并单元格列（团队/小组列）
- 删除全空行、全空列
- 删除口径说明行（关键词：口径说明、注：、备注）
- 排除大区总计（台湾、欧美澳、港澳总计）
- 排除子表头残留（停课数、唤醒率等）

### 3.3 4.1 板块（5 表整合）

**整合主键**：（团队 + LP）联合主键

**列序**：
团队 → LP → 首通语义点执行（5列）→ 首通（7列）→ 首课语义点执行（2列）→ 首课（4列）→ 首专（4列）→ LP入职时长（3列）

**整合逻辑**：
1. 报表1（首通）：仅保留"月度"大组，前缀改为"首通_"
2. 报表2（首课）：仅保留以"首课"开头的列
3. 报表3（首专）：仅保留以"首专"开头的列
4. 报表4（SOP）：分别提取"首通"和"首课"大组
   - 改名为 "首通语义点执行_xxx" / "首课语义点执行_xxx"
5. 报表5（LP架构）：提取入职时间、离职时间、入职时间分组
6. 以报表2 为基础，按 (团队, LP) LEFT JOIN 其他

**排序**：
1. 海外团队总计（全局汇总）
2. 各小组总计（按 TEAM_ORDER：港澳1组、港澳2组、港澳组、美澳1-5组、台湾组）
3. 各小组个人 LP

### 3.4 4.2 组班意向（含计算列）

在 LP 左侧新增 3 列汇总：
- 当前意向等待学员数 = sum(所有等待学员数列)
- 2个意向及以上学员占比加权 = sum(等待学员数 × 占比)
- 多意向占比 = 加权 / 当前意向等待学员数

### 3.5 4.5 服务月跟进（提取服务池）

从转介绍报表中提取**服务池**列（列113-125）：
- 服务池-学员数
- 服务池-外呼跟进率
- 服务池-外呼有效跟进率
- 服务池-微信外呼跟进率
- 服务池-微信覆盖率
- 服务池-微信有效回复率
- 服务池-综合有效跟进率
- 等其他池子相关字段

### 3.6 4.5 服务池SOP

只保留服务池部分（列34-40），列序：
小组 → 负责人 → LP → **语义点执行率加和**（移到LP右边）→ 命中服务池学员数 → 学情反馈执行率 → 学习规划执行率 → 询问家长是否辅导执行率 → 告知转介绍权益执行率 → 告知剩余课时执行率

## 五、结论生成规则（参考文档格式）

参考：https://my.feishu.cn/docx/SbLFdUogiouIErx0zpXcw4krnij

**callout 结构**（每个板块一个）：

```xml
<callout emoji="❗">
<p><b>整体：</b>[关键指标汇总]</p>

<p><b>亮点</b></p>
<p>·[小组+具体数据]</p>
<p>·[小组+具体数据]</p>

<p><b>风险</b></p>
<p>·[落后小组+具体百分比]</p>
<p>·[落后LP+具体百分比]</p>

<p><b>待办</b></p>
<p>·[具体可执行行动]</p>
<p>·[具体可执行行动]</p>
</callout>
```

### 各板块结论关键指标

| 板块 | 整体指标 | 落后判定阈值 |
|---|---|---|
| 4.1 | 首通/首课/首专跟进率+及时跟进率、企微绑定率、秒挂占比、添加企微执行率 | 首通及时<95%、首课/首专及时<85%、企微绑定率<60% |
| 4.2 | 多意向占比、等待学员数 | 占比<整体均值×0.7 |
| 4.3 | 营销/服务类群发条数、个人群发占比 | 占比<整体均值×0.5 |
| 4.4 | 停课占比、90天内唤醒率、外呼跟进率 | 停课>6%目标、唤醒<整体均值×0.5 |
| 4.5 服务月 | 服务池外呼跟进率、综合有效跟进率 | 跟进率<整体均值×0.7 |
| 4.5 SOP | 语义点执行率加和 | <2.4目标 |
| 4.6 外呼 | 覆盖率、生均呼次（含月环比） | 覆盖率<整体均值×0.7 |
| 4.6 企微 | 整体回复比、发送条数 | **回复比>整体均值×1.3（回复比越高=回复消息数越少，越不好）** |

### 落后LP识别门槛
| 板块 | LP最小数据量门槛 |
|---|---|
| 4.1 | 新生数 ≥ 3 |
| 4.4 | 停课占比 > 10% |
| 4.5 | 学员数 ≥ 5 |
| 4.6 外呼 | 学员数 ≥ 50 |

### 结论格式要求
**风险部分**：落后小组后面必须下拆到该组内的落后LP
- 示例：`美澳3组外呼跟进率28.18%，组内落后LP：曲慧(0%)、张弛(7.81%)`

## 九、关键工具命令参考


## 十、可能的失败场景与处理

| 场景 | 处理方式 |
|---|---|
| BI 下载超时（180s） | 自动重试 1 次 |
| 报表无数据 | 自动刷新 1 次后报错给用户 |
| BI 字段名不匹配 | 通过 `bi_skill profile` 词典自动解析正确字段名 |
| 飞书 API 限流 | 分批写入，每批间隔 0.2s |
| 单元格含 < > 符号 | 自动替换为全角 < > |
| 数据 NaN 导致色阶失败 | 跳过该单元格，仅对有值单元格上色 |
| Windows GBK 编码 | 强制设置 PYTHONIOENCODING=utf-8 |
